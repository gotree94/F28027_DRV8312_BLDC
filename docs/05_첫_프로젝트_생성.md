# 05. 첫 프로젝트 생성

F28027 전용 CCS 프로젝트를 만들고, 하드웨어 연결까지 검증합니다.

## 5.1 CCS에서 새 프로젝트 만들기

1. **File → New → CCS Project**
2. Target 선택:
   - **Device**: `TMS320F28027` (보드가 LaunchPad면 `TMS320F28027` 계열 선택 후
     "Connection: Texas Instruments XDS100v2/XDS110")
3. 프로젝트 설정:
   - Compiler: TI C2000 (설치된 최신 또는 지정 버전)
   - Output type: Executable
   - **Linker command file**: 아래 중 하나 선택 또는 생성
     - RAM에서 실행: `28027_RAM_lnk.cmd` (F2802x device support에 있음)
     - FLASH에서 실행: `F28027.cmd` + `F28027_CodeStartBranch.asm`
   - Include options (Runtime): 기본

> controlSUITE의 device support 경로:
> `C:\ti\controlSUITE\device_support\f2802x\v230\`
> 이 안에 `F2802x_Device.h`, `F2802x_GlobalVariableDefs.c`, `F2802x_CpuTimers.c` 등
> 디바이스 초기화 소스와 링커 cmd가 들어 있습니다.

## 5.2 프로젝트 폴더 구성

```
<프로젝트>/                 # 예: C:\ti\workspace\F28027_BLDC_Demo
├── include/                # 사용자 헤더
├── src/                    # 사용자 소스 (main.c 등)
├── device_support/         # f2802x v230 관련 파일 (복사해서 사용)
│   ├── F2802x_Device.h
│   ├── F2802x_GlobalVariableDefs.c
│   ├── F2802x_DefaultIsr.c
│   ├── F2802x_CodeStartBranch.asm
│   ├── F28027_RAM_lnk.cmd
│   └── F28027.cmd
├── driverlib/              # (선택) 최신 C2000Ware driverlib 사용 시
└── ...
```

> **권장 사항**: controlSUITE 원본을 건드리지 말고, 필요한 파일을 프로젝트로
> 복사해 사용합니다. 버전 관리(git)를 하면 진행 과정을 추적하기 좋습니다.

## 5.3 최소 main.c (하드웨어 검증용: GPIO 토글 + 타이머)

아래 코드는 F2802x 헤더만으로 동작하는 최소 예시입니다.

```c
#include "F2802x_Device.h"

// 시스템 클럭 초기화 (60 MHz: 10MHz 크리스탈 * 6 배율 등)
void InitSysClk(void) {
    // 참고: F2802x_Examples.h에 DEFAULT_CPU_FREQ(60MHz)가 정의됨
    // PLL 설정은 데이터시트/controlSUITE 예제 참고
}

void main(void) {
    InitSysCtrl();            // f2802x device support 제공
    DINT;                     // 인터럽트 비활성

    InitGpio();               // GPIO 기본 초기화
    // GPIO0을 출력으로
    EALLOW;
    GpioCtrlRegs.GPAMUX1.bit.GPIO0 = 0;      // GPIO
    GpioCtrlRegs.GPADIR.bit.GPIO0  = 1;      // output
    EDIS;

    for (;;) {
        GpioDataRegs.GPATOGGLE.bit.GPIO0 = 1;   // 토글
        DELAY_US(500000);                        // 0.5s (절대 지연용 루프)
    }
}
```

> 실제로는 `DELAY_US` 를 직접 쓰기보다 타이머나 ePWM 인터럽트를 사용하는 것이
> 정석입니다. 위는 "보드 연결 검증"용 최소 코드입니다.

## 5.4 빌드 및 디버그

1. **Project → Build All** (Ctrl+B)
   - 오류 없이 `.out` 생성 확인
2. **Run → Debug** (Ctrl+F11)
   - Target Configuration이 자동 생성되며 XDS 연결 시도
   - LaunchPad/Experimenter Kit는 USB만 꽂으면 됨
3. **Run → Resume** 후 오실로스코프/멀티미터로 GPIO0 토글 확인
   - GPIO0에 LED가 있으면 깜빡임 확인
4. **Debug 중지 후 Run → Terminate All** 로 세션 종료

### 플래시에 프로그램 넣기 (전원 꺼도 실행)
- RAM에서 실행 중일 때는 전원을 끄면 프로그램이 사라집니다.
- **FLASH 빌드**로 전환:
  - 링커 cmd를 `F28027.cmd`(FLASH)로 변경
  - `F28027_CodeStartBranch.asm` 추가 (reset 벡터에서 C 부트 실행)
  - **Run → Load Program** 후, **Scripts → Flash → Download** 또는
    **Load → Flash Only** 옵션 사용
- 최종 펌웨어는 FLASH 빌드로 배포합니다.

## 5.5 키트 예제(controlSUITE)를 F28027로 마이그레이션할 때

`BLDC_Sensored`는 기본적으로 F28035용입니다. F28027로 전환하려면:

1. **Target 변경**: Project Properties → General → Target device를
   `TMS320F28027`으로 변경
2. **include 경로 변경**:
   - `...\device_support\f2803x\v127\...` → `...\device_support\f2802x\v230\...`
   - 헤더 이름도 `DSP2803x_Device.h` → `F2802x_Device.h` 등으로 변경
3. **링커 cmd 변경**: `F28035_FLASH.cmd` → `F28027.cmd`
4. **핀맵/레지스터 정리**: ePWM 모듈 수(F2802x는 4개), ADC 채널, GPIO mux 차이 반영
5. **빌드 레벨** 방식의 프로젝트는 `LEVEL` 매크로로 단계별 컴파일 가능
   (docs/07 참고)

> 이 마이그레이션은 난이도가 있으므로, **우리 프로젝트는 처음부터 F28027용 빈
> 프로젝트로 시작**해서 필요한 기능을 하나씩 추가하는 것을 권장합니다.
> 키트 소스는 "동작 원리와 초기화 시퀀스 참고용"으로 사용합니다.

## 5.6 문제 해결

| 증상 | 확인/해결 |
|----|----|
| Target connection failed | USB 케이블/포트, 드라이버(XDS100v2/XDS110), 타깃 전원 |
| "No debug probe found" | CCS의 Target Configuration에서 연결 타입 확인 |
| 빌드 시 헤더 없음 오류 | include 경로에 `F2802x_...` device support 추가 |
| RAM 실행 후 재부팅 시 동작 안 함 | FLASH 빌드/다운로드 확인 (5.4 참고) |
| Watchdog 리셋 | `InitSysCtrl()` 안에서 watchdog disable 확인 |
| 크리스탈 부팅 안 됨 | X1/X2와 부트모드 핀(GPIO12/14/16 등) 상태 확인 |
